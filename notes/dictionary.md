# 自分専用辞書

学習中に出てきた言葉や、つまずいたエラーとその解決策をためていく辞書です。

---

## 言葉

### Cursor と Claude Code の違い
- **Cursor**：AI が組み込まれた「メモ帳（エディタ）」。自分でファイルを開いて書きながら、隣の AI に相談したり、書き方を提案してもらったりする。
  - 例え：**運転は自分、助手席にナビ役の AI**。
- **Claude Code**：お願いを伝えると、AI が自分でコマンドを実行したりファイルを作ったり直したりしてくれる「作業代行役」。
  - 例え：**行き先を伝えると AI が運転してくれる**。自分は「ここで曲がって」「ここでストップ」と指示や確認をする。

### Git（ギット）
ファイルの「セーブデータ」を管理する道具。いつ・何を変えたかを記録して、昔の状態にも戻れる。

### git init（イニット）
フォルダを「セーブ機能つき」にする最初の1回だけの準備。
- 例え：ゲームを始めるときに**セーブデータ用のスロットを作る**こと。

### git add（アド）
次のセーブに入れるファイルを選ぶ（＝「ステージング」）。
- 例え：セーブする前に**持ち物を「セーブ用のカゴ」に入れる**こと。

### git commit（コミット）
カゴに入れた変更を、メッセージつきで1つのセーブデータとして記録する。
- 例え：**セーブポイントでセーブする**こと。「ボス前」のような名前（＝コミットメッセージ）をつけておくと、あとで見返しやすい。

### git push（プッシュ）
手元のセーブデータを GitHub（ネット上の保管庫）に送る。
- 例え：**セーブデータをクラウドにアップロード**すること。パソコンが壊れてもデータが残る。
- `git push -u origin main` の `-u` は「次からは `git push` だけで同じ場所に送ってね」という設定。初回だけつければよい。

### git remote add origin（リモート）
GitHub 上の保管庫の住所（URL）を「origin」という名前で登録する。
- 例え：**クラウドのセーブ先を登録する**こと。

### GitHub（ギットハブ）
Git のセーブデータを預けておくネット上の保管庫。

## つまずいたこと・エラーと解決策

### ファイルを編集したのに「変更なし」と言われた
- **原因**：エディタで書いた内容がまだファイルに保存されていなかった（または、すでにコミット済みの内容と同じだった）。
- **解決策**：ファイルを編集したら、必ず **Ctrl + S で保存してから**コミットする。
  - 例え：ゲームで**メニューの「セーブ」を押す前に電源を切ると、進めた分が消える**のと同じ。

### git remote add で URL にカッコがついてエラー
- **原因**：コピーした URL にマークダウン記号の `[ ]` や `( )` が混ざっていた。
- **解決策**：`https://github.com/ユーザー名/リポジトリ名.git` の形だけで登録し直す。

### 初回 push で「Authentication failed」（認証失敗）
- **原因**：GitHub に「本人です」とまだ証明していなかった。AI が裏側で実行するコマンドからはログイン画面を出せない。
- **解決策**：自分で入力欄に `! git push -u origin main` と打って実行し、開いたログイン画面で GitHub にサインインする。1回ログインすれば、その情報がパソコンに保存されるので、次からは AI も push できる。
  - 例え：**新しいゲーム機で初めてクラウドセーブを使うときだけ、アカウントへのログインが必要**なのと同じ。

### 「LF will be replaced by CRLF」という警告
- **意味**：Windows と Mac/Linux では改行の書き方が少し違うので、Git が自動で合わせてくれるというお知らせ。
- **対処**：エラーではないので気にしなくてよい。
